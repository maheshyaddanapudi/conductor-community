# conductor-community

Community-contributed plugin modules for Netflix Conductor (workflow orchestration engine). Java 17, Gradle 7.6.2, Spring Boot 2.7.16. Provides pluggable implementations for persistence (MySQL, PostgreSQL), indexing (Elasticsearch 7), event queues (AMQP, NATS, Kafka), external payload storage (Azure Blob, PostgreSQL), distributed locking (ZooKeeper), and metrics (Prometheus, Datadog).

Conductor core version: 3.15.0. Group ID: `com.netflix.conductor`.

## Essential Commands

```bash
# Fast build (skip tests) — use for compilation checks
./gradlew build -x test

# Full build with tests (requires Docker for Testcontainers)
./gradlew build

# Run tests for a specific module
./gradlew :persistence:conductor-postgres-persistence:test

# Run a single test class
./gradlew :persistence:conductor-postgres-persistence:test --tests "*.PostgresExecutionDAOTest"

# Run a single test method
./gradlew :persistence:conductor-postgres-persistence:test --tests "*.PostgresExecutionDAOTest.testTaskExecLog"

# Run a Spock specification
./gradlew :task:conductor-kafka:test --tests "*.KafkaPublishTaskSpec"

# Check code formatting (Spotless — Google Java Format AOSP)
./gradlew spotlessCheck

# Auto-fix formatting violations — run before every commit
./gradlew spotlessApply

# Generate code coverage report (JaCoCo)
./gradlew jacocoTestReport

# Build Spring Boot executable JAR
./gradlew :community-server:bootJar

# Refresh dependency locks (required for build-related PRs)
./gradlew generateLock saveLock
```

## Architecture

Plugin/SPI architecture using Spring Boot auto-configuration. Each module implements a Conductor contract (`EventQueueProvider`, `ExternalPayloadStorage`, `IndexDAO`, etc.) and is activated at runtime via `@ConditionalOnProperty`. The `community-server` module assembles all plugins into a single Spring Boot JAR. Conductor core (`conductor-core`, `conductor-rest`) is an external dependency — this repo only provides pluggable backends.

## Code Patterns

- **ALWAYS** add the Apache 2.0 license header to new Java files — Spotless enforces it from `licenseheader.txt` and the build will fail without it.
- **ALWAYS** use `@ConditionalOnProperty` to gate new module configurations — every module uses this pattern for runtime activation (e.g., `conductor.db.type`, `conductor.event-queues.amqp.enabled`).
- **ALWAYS** run `./gradlew spotlessApply` before committing — the build runs `spotlessCheck` and will reject unformatted code. Format is Google Java Format AOSP with import order: `java` → `javax` → `org` → `com.netflix` → others → static.
- **ALWAYS** place configuration classes in a `.config` subpackage with `@Configuration` + `@EnableConfigurationProperties` — see `PostgresConfiguration`, `AMQPEventQueueConfiguration` for the pattern.
- **ALWAYS** place DAO implementations in a `.dao` subpackage — see `PostgresExecutionDAO`, `MySQLMetadataDAO`.
- **NEVER** manually edit `dependencies.lock` files — they are auto-generated by `./gradlew generateLock saveLock`.
- **NEVER** add new dependencies to individual module `build.gradle` files without adding the version to `dependencies.gradle` first — all versions are centralized there.
- **NEVER** use `DataSourceAutoConfiguration` directly — the main class explicitly excludes it (`@SpringBootApplication(exclude = DataSourceAutoConfiguration.class)`) and each persistence module manages its own datasource conditionally.
- **ALWAYS** extend `ExecutionDAOTest` (in `common-persistence`) when writing tests for a new persistence DAO — MySQL and PostgreSQL modules both follow this pattern.
- **ALWAYS** set `maxParallelForks = 1` in `build.gradle` for modules with Testcontainers database tests — MySQL and PostgreSQL tests share an embedded database and cannot run in parallel.

## Task Delegation

When working on tasks in this repository, follow this delegation pattern:

### Default Chain
1. **planner**: Analyze the request. Identify which module(s) are affected using `docs/architecture/modules.md`. Check if changes cross module boundaries. Determine if `dependencies.gradle` or `settings.gradle` need updates.
2. **implementer**: Implement changes following Google Java Format (AOSP). Ensure `@ConditionalOnProperty` activation patterns are preserved. Add Apache 2.0 license headers to new files.
3. **test-engineer**: Run tests for affected modules only (see commands above). Ensure Docker is available for Testcontainers. Remember `maxParallelForks = 1` for MySQL/PostgreSQL modules.
4. **reviewer**: Verify `./gradlew spotlessCheck` passes. Confirm import ordering (`java → javax → org → com.netflix → others`). Check that no `dependencies.lock` files were manually edited.
5. **security-auditor** (conditional): If changes touch REST controllers, SQL queries, credential handling, or deserialization logic, audit for OWASP Top 10 vulnerabilities. Read-only — produces findings, not code.

### Event Queue Tasks (AMQP, NATS, Kafka)
When the task involves `event-queue/*` or `task/kafka`:
- The implementer must understand the `EventQueueProvider` / `ObservableQueue` contracts from conductor-core
- Key files: `AMQPObservableQueue.java`, `AMQPEventQueueProvider.java`, `AMQPEventQueueConfiguration.java`
- AMQP has the most complex configuration surface (see `AMQPEventQueueProperties`)
- Test with: `./gradlew :event-queue:conductor-amqp:test`

### Persistence Tasks (MySQL, PostgreSQL, Elasticsearch)
When the task involves `persistence/*` or `index/*`:
- The implementer must understand the DAO contracts (`ExecutionDAO`, `MetadataDAO`, `QueueDAO`, `IndexDAO`) from conductor-core
- Schema changes require Flyway migrations in `src/main/resources/db/migration*`
- Tests require Docker and run sequentially (`maxParallelForks = 1`)
- Test with: `./gradlew :persistence:conductor-postgres-persistence:test`

### Dependency Updates
When updating dependency versions:
- Edit version in `dependencies.gradle`
- Run `./gradlew build -x test` to verify compilation
- Run `./gradlew generateLock saveLock` to refresh lock files
- Do NOT manually edit `dependencies.lock` files

### Subagent Fallback
If a subagent fails to load:
1. Inform the user which agent could not be loaded
2. Read `.claude/agents/{agent-name}.md` for that agent's instructions
3. Follow that agent's instructions directly in the main context

## Verification Checklist

Before any PR or commit, verify ALL of the following:

1. **Build passes**: `./gradlew build -x test` succeeds without errors
2. **Formatting clean**: `./gradlew spotlessCheck` passes (run `spotlessApply` to fix)
3. **License headers present**: All new Java files have the Apache 2.0 header from `licenseheader.txt`
4. **Tests pass for affected modules**: Run the specific module test command from the quick reference table above
5. **No manual lock file edits**: `dependencies.lock` files are only modified via `./gradlew generateLock saveLock`
6. **Import order correct**: `java` → `javax` → `org` → `com.netflix` → others → static `com.netflix` → static others
7. **Conditional activation preserved**: New `@Configuration` classes use `@ConditionalOnProperty` matching the module's activation property
8. **Commit message is descriptive**: Simple imperative style (e.g., "Fix AMQP queue ack behavior", "Add SSL support for NATS connection")

## Do Not Modify

These paths are protected. Do not edit, delete, or overwrite them:

- `.github/` — CI/CD workflows and PR template
- `gradle/` — Gradle wrapper distribution
- `gradlew`, `gradlew.bat` — Gradle wrapper scripts
- `licenseheader.txt` — License header template enforced by Spotless
- `settings.gradle` — Module registration (unless adding a new module)
- `build.gradle` — Root build configuration (unless changing global build behavior)
- `**/dependencies.lock` — Auto-generated; use `./gradlew generateLock saveLock`
- `**/src/main/resources/db/migration*` — Flyway migrations (append-only; never modify existing migrations)
